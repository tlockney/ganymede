## 2026-11-20, Engine benchmark in ganymede-ffi (#892)

The V8 spike's benchmark runner (#646, `spikes/v8-engine`) now lives in
`ganymede-ffi` behind an off-by-default `v8-bench` feature, so the Mac and
iOS apps can run it from a Settings button. They link ganymede-ffi as a
static library (GanymedeFFI.xcframework), and a second Rust static library
in the app would clash with its Rust runtime symbols, so the benchmark goes
in the one they already have.

- **C ABI** (`ganymede.h`): `ganymede_v8_bench_available()` (1 with the
  feature), `ganymede_v8_bench_run(config_json)` and
  `ganymede_v8_bench_free(s)`. All three are exported with and without the
  feature, so the Swift side links either way; without it a run returns
  `{"error": "built without V8 ..."}`. The config and the report are the
  spike's `v8_spike_run` ones.
- **Threads.** A run happens on a `std::thread` of its own with an 8 MB
  stack, joined before the call returns: V8 sizes its stack limit from the
  thread it runs on, so the caller's stack doesn't matter. A `Mutex`
  serializes calls, since V8's platform and flags are process-global. V8
  initializes once per process (`OnceLock`); the first call's `jitless`
  stays for the process, and the report shows which one ran.
- **Errors, not crashes.** NULL, invalid UTF-8 and invalid JSON give an
  error report. A panic is caught with `catch_unwind` (the release profile
  keeps the default `unwind`, so it works) and gives one too. A workload
  whose script throws carries `error` in its own entry and the rest still
  run.
- **Builds.** `scripts/build-xcframework.sh` builds all three slices with
  `v8-bench` and fails if a slice's library has no V8 symbol. rusty_v8
  downloads a prebuilt static V8 per target, with no check of its own
  unless `RUSTY_V8_ARCHIVE_SHA256` is set: `scripts/v8-archive-sha256.sh`
  holds the SHA-256 of each archive (aarch64 macOS, iOS device and
  simulator, x86_64 Linux), and the script, `ffi-smoke.sh` and CI set the
  variable from it. It fails when Cargo.lock's `v8` isn't the version it
  pins. The iOS device library has no JIT (the simulator's keeps it), so
  the device report always says `jitless: true`. Default builds don't
  pull `v8` in (`cargo tree -p ganymede-ffi` has no `v8` without the
  feature). `v8` is exact-pinned to the spike's `=152.2.0`.
- **Limits.** `repeats` over 1000 is an error report. A workload that
  never returns holds the lock, and V8 running out of heap aborts the
  process; the header says so. A failed V8 initialization is remembered, so
  a second call reports it instead of initializing again.
- **Notices.** The release's `THIRD-PARTY-NOTICES` for the XCFramework
  is generated with `--features v8-bench` and gets
  `crates/ganymede-ffi/V8-NOTICES.txt` appended: V8's BSD-3-Clause and the
  bundled C++ code's licenses. The `v8` crate package carries no license
  files, so that list is from the components' upstream licenses, and should
  be rechecked when V8 is updated.
- **CI.** The `ffi` job runs `cargo clippy`, `cargo test` with
  `--features v8-bench` and `scripts/ffi-smoke.sh` with the feature
  (`FFI_FEATURES`, which also expects the benchmark to be available) on both
  cells, so the header is checked against both builds. The macOS cell also
  builds the XCFramework, so it downloads V8 for three targets, and the
  Linux cell for one.
- **The spike stays**, still not a workspace member, for the size scripts,
  the host runner and the bench app. It and `v8_bench.rs` hold the same
  runner by copy; `spikes/v8-engine/README.md` says to change both. The
  unit tests inline the `start` workload instead of including it from
  `spikes/`, whose changes don't run the crate's CI.
- **Not covered here.** The Swift Settings button, and what the XCFramework
  grows by (V8 is tens of MB per slice); neither is measured here.

The `audit` job flagged `paste` (RUSTSEC-2024-0436, unmaintained, no vulnerability), a proc macro that only v8 brings in; deny.toml ignores it with that reason until v8 drops it or V8 leaves the apps.
