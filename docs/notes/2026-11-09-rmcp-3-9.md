## 2026-11-09, rmcp 3.9.0 for RUSTSEC-2026-0462 (#603)

cargo-deny's `audit` job started failing on every PR: RUSTSEC-2026-0462
says rmcp's Streamable HTTP clients before 3.9.0 buffer a response body
with no size limit. Ganymede enables only rmcp's server features
(`server`, `transport-io`, `transport-streamable-http-server`), so the
affected client code isn't built. The lockfile moves to rmcp 3.9.0 anyway,
so `audit` passes without an ignore.

Only the `rmcp` and `rmcp-macros` entries changed. A plain
`cargo update -p rmcp` with a newer local cargo also re-resolved
unrelated `windows-sys` and `getrandom` edges, so those hunks were left
out; `cargo metadata --locked` accepts the result.
