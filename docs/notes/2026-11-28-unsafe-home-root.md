## 2026-11-28, refuse an unsafe default root (#989)

Without `--root-dir` and `root_dir` in the config file, the server serves the home directory of the user running it. When there is no usable home directory it now refuses to start with an error asking for `--root-dir`, where #988 fell back to the current directory and logged a warning. A home counts only if `dirs::home_dir()` names an existing directory whose canonical path isn't `/`: a home of `/` would serve the whole disk, and the old current-directory fallback was unstable and could expose `/` under launchd or systemd, which start a service there. The server checks this in `ServeArgs::into_config_with`, so every command that serves (`serve`, `lab`, `ui`) exits non-zero before anything creates directories under a missing `HOME`. An explicit `--root-dir /` or `root_dir = "/"` is still the user's choice and works, and the config file's `root_dir` counts as explicit, so a broken `HOME` doesn't stop a service whose file names its root. `config::default_root_dir` returns the usable home or `None`; only `Config::default()` still has a path, `.`, which the serve path never reaches because the check refuses first, and the embedded server passes its own root. One case is left as is: with a missing `HOME` and an explicit root, the server still creates `$HOME/.local/share/ganymede/recovery`, so a later start without `--root-dir` serves that new, nearly empty home (the root was explicit, and the next default start is still a real directory owned by the user).
