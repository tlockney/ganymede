## 2026-11-11, host API: a notebook edits its own cells (#656)

The second step of [A host API for kernels](../host-api.md): `self.add`,
`self.edit` and `self.delete` on the kernel's own notebook, the one whose
session the server started it for. They edit its document room, so
JupyterLab and the apps see the change live, and a room with no client
saves before it retires, as for the execute endpoint. An edit or delete
names the source hash `notebooks.read` returned for the cell (MurmurHash2,
seed 0, as the execute endpoint checks); a cell changed since fails
`source_mismatch`, so a notebook can't overwrite an edit it hasn't seen.

`[host] edit_self` (default `true`) turns the calls off for every
notebook, and `hello` lists them only when they're on and the kernel has
a notebook. New cells get empty metadata: the MCP tools' agent provenance
says an agent wrote the cell, which isn't so here.
