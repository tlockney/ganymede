## 2026-11-14, One room-ops helper (#768)

The MCP cell tools, `ganymede execute`'s runs and the host API's `self.*`
calls each had their own copy of the room edits: reading a cell's
source, inserting a cell, replacing a source, deleting one, and the
read-only refusal for a room another server owns. They now share
`crates/ganymede-server/src/room_ops.rs`. Checks that differ by caller
(MCP's read marks, the `self.*` source hash) stay with the caller.

Two behaviors follow from sharing the code:

- `self.add` stamps `metadata.ganymede.agent` with `by: "kernel"`, and
  `self.edit` keeps the replaced source in `history`, as `cell_edit`
  does. Before, `self.*` edits carried no provenance.
- `self.*` calls hold the notebook's room, as an MCP connection does.
  A server-started kernel whose notebook has no client open could see
  the room retire between calls, and in a notebook without cell ids
  (nbformat 4.4) the ids `self.add` returned would change. The hold is
  per kernel. A task watching the kernel lets it go when the kernel
  manager shuts the kernel down, and `unpin` lets a pinned kernel's go,
  so an ended kernel doesn't keep its notebook's room open and locked.

`source_of` now also reads a source stored as a list of strings, which
the `self.*` hash check and `execute` read as empty before.
