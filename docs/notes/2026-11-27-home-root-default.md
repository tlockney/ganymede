## 2026-11-27, serve the home directory by default (#955)

With no `--root-dir` and no `root_dir` in the config file, `ganymede serve`, `lab` and `ui` now serve the home directory of the user running the server (`config::default_root_dir`), where they served the process's current directory. A server that launchd or systemd starts in `/` would otherwise expose the whole disk, so the default is the conservative one. Without a home directory (it is unset or not a directory) the server falls back to the current directory and logs a warning. `--root-dir` and `root_dir` override the default as before, and the server info file reports the resolved root. `jupyter_server` still defaults to the current directory, so this differs from it; the docs say so. `ganymede mcp` and `ganymede grant` keep the current directory as their default. `mcp` finds a running server by checking that the server's root is a prefix of the current directory, so a server rooted at the home directory is still found from any directory under it. Tests that start a server from a temp directory without `--root-dir` now pass it, so they don't serve the developer's home.

A grant belongs to the root it was made under, and `ganymede grant --root-dir` still defaults to the current directory. So with `cd ~/proj && ganymede serve`, the server is now rooted at `~` and a `ganymede grant` run in `~/proj` stores its grant under a root the server doesn't read. The docs (reference.md's `grant` section and host-api.md) say to use `ganymede grant --root-dir ~ …` or start the server with `--root-dir .`; `grant`'s own default is unchanged. The examples that `cd` into a notebooks folder and start `lab` or `serve` now pass `--root-dir .`, which works on the latest release and on `main`.
