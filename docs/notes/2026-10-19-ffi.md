## 2026-10-19, ganymede-ffi: the server in-process for the Swift shell (#157)

The macOS app runs the server in its own process and loads ganymede-ui
from it in a web view, so the Rust side it needs is small: start, URL,
stop. `ganymede-ffi` exposes that as four C functions declared in
`crates/ganymede-ffi/include/ganymede.h`. The config is JSON with
`ganymede.toml`'s keys, so the app and the config file share one schema;
`port` defaults to 0 there.

- The server runs on its own thread with a multi-thread tokio runtime;
  `start` blocks until `on_listening` fires or `run_with` fails, and
  `stop` sends on a channel and joins the thread, which shuts kernels
  down first.
- `Startup::stop` replaces the signal handlers and the URL on stdout: an
  app must not take over SIGINT/SIGTERM or write to stdout.
- A hand-written header with no cbindgen: four functions. CI links
  `tests/smoke.c` against the static library through it on Linux and
  macOS, so drift fails to link.
- `scripts/build-xcframework.sh` builds macOS (arm64 + x86_64, lipo),
  iOS and the iOS simulator and runs `xcodebuild -create-xcframework`
  with a `GanymedeFFI` module map. The macOS CI job uploads the zip as an
  artifact. iOS links today with ZeroMQ and subprocesses compiled in;
  #160 removes them from that build.
- The debug static library is about 430 MB (everything, unstripped);
  release with thin LTO is the one that ships.
