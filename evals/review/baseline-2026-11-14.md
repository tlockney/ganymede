# Baseline: review prompt, 2026-11-14

First run of the review replay eval (#822) on the prompt as it stood on
2026-11-14 (Gaps entries 1 to 16). Produced by
`node evals/review/run.mjs --prompt review-prompt.md --runs 2 --concurrency 3`,
then one `--lens security` and one `--lens concurrency` run on the ten cases
with a class A or B finding. This is the second baseline; the first had
flaws (see the dev log) and was discarded. Read it with these caveats:

- **The prompt has seen these cases.** Gaps entries 1 to 16 name most of them
  (ganymede #741, #757, #730, #654, #817, #665; ganymede-ui #510, #525, #540,
  #471; ganymede-device #80; cdp-kernel #476, #480) and add the check each one
  motivated, so recall here is optimistic for the same defects and says little
  about a fresh miss. The set's use is to catch a regression and to measure a
  new entry on its own case, not to predict recall on unseen diffs.
- **Small numbers.** 20 findings, 2 runs, 5 clean cases. One finding is 5 points.
- **No builds or tests** in the reviews (read-only tools), so class E is
  understated. "Other Medium+" findings are what the review rated, judged
  by Sonnet; they were not checked, so some false alarms may be real findings.
- **Two prompt files.** The plain and security-lens runs used prompt sha
  f4471519; `review-prompt.md` gained Gaps entry 17 (a root-keyed state check,
  #827) while they ran, so the concurrency-lens runs used sha 0f3b111e. Each
  entry in `results.json` records its sha. The difference is one changelog
  entry.
- **The runner was hardened after this baseline.** It ran on the runner of
  commit 7dfbe2e. That runner passed no settings isolation (the user's and
  project's own permission rules merged in), still allowed `git blame` (so
  `--contents` could read files outside the clone), built its denies from a
  blanket `/home` and `/mnt`, did not date-limit the issue's comments, let one
  `--out` mix prompt shas (the concurrency-lens runs did), and did not check
  that `gh` works first. The current runner fixes these. A rerun with the
  current runner is the next baseline; compare against it rather than treating
  these numbers as final.
- **Cases added later.** `ganymede-827` and `ganymede-827-copy-test` (Gaps
  entries 17 and 18) were added after this baseline ran; its numbers cover
  the other 21 cases.
- The judge was spot-checked on the one High that every run missed (ganymede
  #817's master token in the lab page; it was right). The reviews read the
  issue in 57 of 62 runs.


- Prompt: `/mnt/project-files/reviews/pr-reviewer/review-prompt.md` (sha256 f4471519d14b)
- Review model: opus; judge: sonnet; runs per case: 2; cases: 21
- Total cost: $55.27 (reviews $54.01, judge $1.26)

## Two lenses vs one run

On 13 class A/B findings in 10 cases, one plain run catches 81%, two plain runs 85%, a security-lens run plus a concurrency-lens run 88% (cost of the pair $17.32 against $9.07 for one plain run). Conclusion: not justified by this sample. Rule: justified when the lens pair beats one run by at least 15 points and beats two plain runs.

| Mode | Recall on the A/B findings |
| --- | ---: |
| One plain run (mean of runs 1 and 2) | 81% |
| Two plain runs (best of runs 1 and 2) | 85% |
| Each lens run alone (mean) | 85% |
| Security run + concurrency run (best of the two) | 88% |
