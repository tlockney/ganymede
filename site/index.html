Jupyter server · Rust · no Python

The Jupyter server, without the Python.

Ganymede runs your kernels and serves the same API as jupyter_server, so JupyterLab and VS Code connect to it unchanged. It is one Rust binary, or a library to embed, and it needs no Python environment to run a TypeScript notebook, or any other.

# Rust toolchain
cargo install --git https://github.com/tlockney/ganymede ganymede-cli
ganymede kernelspec list
# Linux, macOS: latest release, plus cdp-kernel if Node 24+ is installed
curl -fsSL https://ganymede-server.com/install.sh | sh
ganymede kernelspec list

Serve, then connect

ganymede serve prints a URL with its token. Paste it into VS Code's Existing Jupyter Server, or open JupyterLab's own bundle from it, and pick any kernel you have installed: cdp-node for TypeScript, python3 if ipykernel is there.

No server at all for scripts and CI: ganymede run sends code to a kernel and prints the output, and ganymede execute writes the same notebook jupyter execute would.

Features

No Python in the product

The server, kernel host, notebook format, and executor are Rust. Python appears only as a kernel someone installed.

Any kernel

Kernels come from the standard kernelspecs in the Jupyter data directories. The host knows no language; the same tests run on cdp-kernel and ipykernel.

Existing frontends

The jupyter_server REST and websocket API, both websocket framings, and JupyterLab's /lab/api/* endpoints.

Parity with jupyter execute

Notebooks come out as nbclient writes them, and saves are byte-identical to Python's nbformat, so git sees no churn.

Embeddable

ganymede-engine is a library: start kernels, execute with streaming output, run notebooks. It builds for iOS, Android, and wasm.

Files as the source of truth

Atomic writes, modification-time conflict checks, and checkpoints outside the notebook folder, so synced folders such as iCloud Drive stay intact.

Where it fits

Ganymede takes jupyter_server's place and keeps both of its interfaces: the API above it and the kernels below.

Connecting a frontend · Roadmap

Why

Nothing in the Jupyter protocols requires Python, but the server does: running a TypeScript notebook means installing a Python environment first. That rules out places Python can't easily go, such as an iPad app. Ganymede keeps the protocols and the ecosystem and drops the dependency.

Architecture · Replacing Python

Status

Early software. An end-to-end suite compares it against jupyter execute and jupyter server on cdp-kernel and ipykernel, on Linux and macOS. Windows builds but is not tested end to end.
