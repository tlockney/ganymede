Notebooks that run like programs, in apps of their own.

Ganymede runs notebooks: in its Mac, iPad and iPhone apps, from the command line, and for coding agents. A notebook can take parameters and return named results, so other tools and other notebooks can call it.

  • The apps. The server runs inside the app. On the Mac it uses the kernels installed there; on the iPad and iPhone, TypeScript runs in the app. Apps
  • Notebooks as programs. Run one from the command line, CI, HTTP, a link, a Shortcut, or another notebook, with JSON in and JSON out. Notebooks as programs
  • Agent journals. An agent works in a notebook over MCP, and the notebook it leaves reruns from the top. Agents
  • TypeScript. cdp-kernel runs cells on Node, Deno, or in the app.

Mac, iPad, and iPhone apps

The apps are the main way to use Ganymede. Each one runs the server inside the app, so there is nothing else to install or start, and each can also use kernels on another server.

Mac

macOS 26 or later, Apple silicon. Signed and notarized: unzip it and move Ganymede.app to Applications. It updates itself, opens ganymede:// links, and gives Shortcuts actions to run notebooks.

Notebooks as programs

A notebook reads its parameters in its first cell, with defaults so it still runs on its own, and publishes results by name. Every caller uses the same run: a fresh kernel from the notebook's kernelspec, the parameters as JSON, the named results back as JSON. Nothing is written into the notebook unless you ask.

The callers: ganymede execute in a script or CI, POST /api/notebooks/run on a running server, a ganymede:// link or a Shortcut on the Mac, and another notebook through the host API, if it has been granted that notebook.

An agent and a person in one notebook

A coding agent usually explores data in its shell and writes it up afterwards from memory. With ganymede mcp, Claude Code or another MCP client works in the notebook instead: each step is a cell that ran on a real kernel, dead ends stay labelled, and you can watch, add cells of your own, and rerun the result from the top.

The ganymede-journal plugin gives the agent a way to keep the notebook as a journal, and ganymede nb publish turns one into a page to share.

TypeScript notebooks

cdp-kernel is a TypeScript kernel built alongside Ganymede. It runs cells on Node, Deno and other runtimes, in a web page, or inside the iPad and iPhone apps. TypeScript, top-level await and npm: imports work, and jupyter.md, jupyter.html, charts and widgets render as rich output.

Works with Jupyter

Ganymede serves the same REST and websocket API as jupyter_server and launches kernels from the same kernelspecs, so JupyterLab, VS Code, ipykernel and other Jupyter tools work with it unchanged. The server itself needs no Python.

Frontends

VS Code's Existing Jupyter Server, JupyterLab served by ganymede lab, and clients of @jupyterlab/services. Connecting a frontend

Kernels

Any installed kernelspec: cdp-kernel, ipykernel, or another. The host knows no language, and the same tests run on cdp-kernel and ipykernel.

Notebook files

Executed notebooks come out as jupyter execute writes them, saves match Python's nbformat byte for byte, and writes are atomic, so git and synced folders see no churn.

Install the command line

# Linux and macOS
curl -fsSL https://ganymede-server.com/install.sh | sh
ganymede lab install   # JupyterLab's frontend, without Python
ganymede lab
# Rust toolchain
cargo install --git https://github.com/tlockney/ganymede ganymede-cli
ganymede kernelspec list
# JupyterLab and cdp-kernel
docker run --rm -p 8888:8888 ghcr.io/tlockney/ganymede

One binary for jupyter server, execute, kernel and kernelspec. Linux and macOS are tested end to end; Windows binaries are built but not tested. It also builds as a library to embed. Install · Embedding

Why

Ganymede began as a way to write TypeScript notebooks and to run notebooks in an iPad app. The Jupyter protocols suit both; the reference server, a Python program, doesn't travel to an iPad. A Rust core runs the same server as a command, inside an app, or behind an agent's MCP session, and keeping the protocols keeps the Jupyter tools and kernels people already have.
