Jupyter server · Rust · TypeScript

Notebooks for TypeScript, agents, and your devices.

Ganymede runs kernels, reads and writes notebooks, and serves the same API as jupyter_server, so JupyterLab and VS Code connect to it unchanged. It is one Rust binary, a library to embed, and the core of its own apps.

  • TypeScript notebooks. cdp-kernel runs cells on Node, Deno, or in the browser, from JupyterLab, VS Code, or the apps.
  • Agent journals. ganymede mcp lets Claude Code or another agent record an analysis in a notebook as it works, cells with their output, for you to read or re-run. Agents over MCP
  • The apps. Mac, iPad, and iPhone, with the server inside the app; on the iPad and iPhone, TypeScript runs on the device. Apps
# Linux and macOS
curl -fsSL https://ganymede-server.com/install.sh | sh
ganymede kernelspec list
# Rust toolchain
cargo install --git https://github.com/tlockney/ganymede ganymede-cli
ganymede kernelspec list
# JupyterLab and cdp-kernel
docker run --rm -p 8888:8888 ghcr.io/tlockney/ganymede

The script also installs cdp-kernel when Node 22.18 or later is there. Linux and macOS are tested end to end; Windows binaries are built but not tested. Other ways to install

Serve, then connect

ganymede serve prints a URL with its token. Paste it into VS Code's Existing Jupyter Server, or open JupyterLab's own bundle from it, and pick any kernel you have installed: cdp-node for TypeScript, python3 if ipykernel is there.

No server at all for scripts and CI: ganymede run sends code to a kernel and prints the output, and ganymede execute writes the same notebook jupyter execute would.

Mac, iPad, and iPhone apps

Ganymede's own notebook app runs the server inside the app, so there is nothing else to install or start. On the Mac, kernels are the ones installed on the Mac; on the iPad and iPhone, TypeScript runs in the app itself. Either can also use kernels on another server.

Mac

macOS 26 or later, Apple silicon. Signed and notarized: unzip it and move Ganymede.app to Applications. It can be the default app for .ipynb files.

Download for Mac Release notes

iPad and iPhone

iPadOS and iOS 26 or later. In testing on TestFlight with a small internal group, and not in the App Store yet. To try it now, build it with Xcode from ganymede-ui's apple/ folder.

Features

No Python runtime

The server, kernel host, notebook format, and executor are Rust, with no Python dependency. Python appears only as a kernel someone installed, as the reference CI compares against, and as the format the notebook writer matches. ganymede lab install unpacks JupyterLab's JavaScript from its PyPI wheel without running Python. Details

Any kernel

Kernels come from the standard kernelspecs in the Jupyter data directories. The host knows no language; the same tests run on cdp-kernel and ipykernel.

Existing frontends

The jupyter_server REST and websocket API, both websocket framings, and JupyterLab's /lab/api/* endpoints.

Parity with jupyter execute

Notebooks come out as nbclient writes them, and saves are byte-identical to Python's nbformat, so git sees no churn.

Embeddable

ganymede-engine is a library: start kernels, execute with streaming output, run notebooks. It builds for iOS, Android, and wasm. Embedding

Files as the source of truth

Atomic writes, modification-time conflict checks, and checkpoints outside the notebook folder, so synced folders such as iCloud Drive stay intact.

Frontends and kernels

Ganymede takes jupyter_server's place and keeps both of its interfaces: the API above it and the kernels below.

Connecting a frontend · Roadmap

Why

Ganymede began as a way to write TypeScript notebooks and to run notebooks in an iPad app. The Jupyter protocols suit both; the reference server, a Python program, doesn't travel to an iPad. Keeping the protocols keeps JupyterLab, VS Code, and the existing kernels, ipykernel included. A Rust core lets the same server run as a command, inside an app, or behind an agent's MCP session.

Architecture · Replacing Python

Status

Early software. An end-to-end suite compares it against jupyter execute and jupyter server on cdp-kernel and ipykernel, on Linux and macOS. Windows builds but is not tested end to end. Known gaps
